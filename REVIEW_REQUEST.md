# Manual external review queue record

Open a catalog issue per first/version review. Title: `Review: app vX.Y.Z`. Never put secrets in an issue. Security reports use private vulnerability reporting instead and receive a response in 48 hours.

- Received (UTC timestamp), submitting author and owner consent:
- App ID, external source repository and open license:
- Requested version, exact source commit, artifact URL, SHA-256:
- Dependency/provenance list and source/build correspondence evidence:
- Real-console test (person/date/model/setup/source/exact artifact hash/results):
- No hidden collection; opt-in behavior; credentials/tokens stay on console:
- No leaked SDK, DRM/paywall bypass or other red-line material:
- Reviewer (independent, or founder Pedro's exception recorded):
- Queue position by received time; target decision within 14 calendar days:
- Missing evidence / security interruption / updated target, with timestamp:
- Decision, date, reviewed version/hash and checklist evidence URL:
- Author last confirmed / expiry deadline (initial 90 + 14 day rule):
- Catalog PR, DCO sign-offs and generated badge/record links:

New versions and replaced assets require a new review; update the prior record's latest-version state immediately. Do not silently reorder requests. Community list admission is separate, best effort, no badge or verification.
